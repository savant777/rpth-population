# Durable receipts in the test copy

Google limits developer metadata to 30,000 characters at spreadsheet level and separately for each sheet. Both keys and values consume that allowance. A full JSON receipt per spreadsheet-level metadata entry exhausted it during QA. See [Google's metadata guide](https://developers.google.com/workspace/sheets/api/guides/metadata).

`ReceiptStore.gs` stores full receipts in hidden `_RPTH Receipts 0001` sheets. A/B hold RequestID/owner hash; C:F hold literal JSON chunks of at most 40,000 UTF-16 units, without splitting surrogate pairs. Row 1 has a strict six-column schema. At row 10000 a new shard is created. Lookup scans only UUID columns and reads the matching payload, preserving owner checks after preview-cache expiry or response loss.

Business changes, the receipt row and a one-character `r` metadata marker succeed or fail in one Sheets batch. The marker keeps the original positive metadata ID derived from RequestID, so an ID collision fails the whole batch instead of duplicating writes. Markers are attached to receipt rows; each shard stays below its independent metadata budget. This remains Google Sheets storage and does not add a database or weaken authentication.

`migrateRegistrationReceiptsInCopy` is an editor-only, guarded test-copy maintenance function. It takes the script lock, copies every legacy receipt exactly, and updates each original marker's key/value/location atomically. It does not delete receipts, metadata IDs, business rows or history. It verifies every full receipt after migration. Legacy lookup remains supported for staged rollout. Keep migration off the web command allowlist.

Apps Script v14 then committed two new web transactions with successful readback: switch request `52cfae3f-3739-4776-82da-a2c6de062bf2` and MAIN promotion `01e4d150-4f9c-4e13-a1d6-7210853e9f03`. Native inspection confirmed 29 receipts in the hidden ledger, both new UUIDs present, and zero legacy keys. Proof is in ignored `local-delivery/receipt-migration-result.txt`, `receipt-migration-success.jpg`, `face-transfer-final-native.txt` and the corresponding web receipts. Response-loss recovery and duplicate-marker atomicity are automated fixture tests, not claimed as online fault injection. Never roll back to the old metadata-only receipt reader after migration.
