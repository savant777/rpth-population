# รายการปรับ UI หลังทำ flow ครบ

เก็บประเด็นจากการทดสอบไว้ที่นี่ก่อน ไม่รวมการแก้ด้านความถูกต้อง/ความปลอดภัยซึ่งต้องแก้ทันที ไม่เปลี่ยนกติกาธุรกิจจากรายการนี้

| ID | จุดที่พบ | สิ่งที่ควรปรับ | สถานะ |
| --- | --- | --- | --- |
| UI-001 | หลัง commit สำเร็จ draftStatus ยังบอกว่ายังไม่ได้บันทึก | แสดงสถานะบันทึกสำเร็จและจัดการแบบร่างให้สอดคล้องกัน | รอท้ายโครงการ |
| UI-002 | รอ preview/commit แล้วปุ่ม disabled แต่ไม่มีข้อความกำลังทำงาน | แจ้งว่ากำลังตรวจข้อมูล/บันทึก พร้อมป้องกันการกดซ้ำ | รอท้ายโครงการ |
| UI-003 | รายละเอียดในสรุปใช้ชื่อคอลัมน์อังกฤษและ true/false | ใช้คำอธิบายไทยและรูปแบบค่าที่อ่านง่าย โดยยังตรวจเทียบกับ schema ได้ | รอท้ายโครงการ |
| UI-004 | บางข้อความยังเรียกบัญชีสดว่าบัญชีตัวอย่าง และ footer ว่า UI Prototype | แยกคำอธิบาย demo/ชีตสำเนา/live ให้ตรงโหมดจริง | รอท้ายโครงการ |
| UI-005 | วันที่ Effective Date ในสรุปเป็น ISO แต่หัวสรุปเป็น dd/MM/yyyy | แสดง dd/MM/yyyy สม่ำเสมอและรักษาค่า API เป็น ISO | รอท้ายโครงการ |
| UI-006 | commit ที่ปฏิเสธเพราะสรุปเก่ายังต่อท้ายว่าลองคำขอเดิมซ้ำ | แยกคำแนะนำ stale/expired ซึ่งต้องสรุปใหม่ ออกจาก network failure ซึ่งต้อง retry request เดิม; ข้อความเหตุผลจาก server ปัจจุบันยังระบุวิธีที่ถูกต้องอยู่ | รอท้ายโครงการ |

ตรวจ desktop/mobile, keyboard, focus, dialog, ข้อความยาว และการแสดงข้อผิดพลาดซ้ำอีกครั้งหลังทุก flow พร้อม ห้ามเปลี่ยนระบบยืนยันก่อนเขียนและการปฏิเสธคำขอซ้ำเพื่อแก้รูปลักษณ์
